# Спот-бот MEXC

Бумажный спот по умолчанию. Ордер на MEXC уходит только если в `.env` стоит ровно `SPOT_LIVE=1` и процесс запущен с `--live`. Это не обещание прибыли и не прогноз. Цепь DUP бот не импортирует.

Повтор без `--once` крутит цикл раз в `SPOT_INTERVAL_SEC` (по умолчанию 60 секунд).

## Деньги

Суммы котировки хранятся целыми: `1 USDT = 1_000_000`. Float и булево значение на этом пути отвергаются. Цена одной монеты хранится в `1e-12` USDT, касса по-прежнему в миллионных: так стоп 3.5% существует и на дешёвой монете. Все пороги ниже — в bps, `100 bps = 1%`.

## Запуск

```powershell
cd C:\Users\vovun\Desktop\Торговля
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
.\.venv\Scripts\python -m spotbot --once
```

| Команда | Что делает |
|---|---|
| `python -m spotbot --once` | Один бумажный цикл RSI |
| `python -m spotbot --mode liquidity --once` | Один цикл ликвидности, отдельная книга |
| `python -m spotbot --sleeves --once` | Три рукава, у каждого своя книга |
| `python -m spotbot.ops_main` | Только страница наблюдения |
| `python -m spotbot.replay_main --symbol BTCUSDT` | Прогон правила по свечам, без ордеров |

Ключи MEXC в исходниках не лежат. Токен Telegram процесс не загружает. Публичные свечи работают без ключей.

## Счета

По умолчанию бумажный счёт в `data/paper/book.json`. Живой счёт пишется в `data/live/` и бумажную книгу не читает. Режим `liquidity` пишет в `data/paper/book_liquidity.json` и с RSI не смешивается.

Книга заменяется целиком. Оборванная запись предыдущий файл не стирает. Файл, который при открытии был бы отвергнут, на диск не пишется. Битая книга не открывается и не затирается. Книга без кассы и позиция без поля не открываются. Книга с отрицательной кассой, двумя строками одной пары или повтором номера клиента не открывается. День охраны не из даты или из будущего книгу не открывает. Пауза после стопа, записанная не как время, книгу не открывает. Пара в книге только из заглавных букв и цифр и оканчивается на `USDT`.

## Рукава

Устойчивые: BTC, ETH. Альты: SOL, XRP, ADA, AVAX, LINK, DOT. Мемы: DOGE, SHIB, PEPE, FLOKI, BONK, WIF. Котировка — USDT. Список пар в настройке не повторяется. Одна и та же пара не входит в два рукава. Слотов от 1 до 14. В каждой книге одновременно одна монета, на всю сумму этой книги.

Прибыль и убыток остаются в своей книге. Новый вклад с основного баланса делится на три и добавляется сверху. 100 USDT делятся как 33.333334 + 33.333333 + 33.333333, чтобы не потерять satoshi. Уменьшить основной баланс и забрать деньги из книг бот отказывается. Казна с суммой не из целого числа, с минусом или с битым файлом деньги не добавляет. Новый вклад пишется вместе с отметкой суммы: повтор после обрыва ту же сумму второй раз не добавляет.

Цикл читает весь список рукава и из прошедших фильтр берёт ту, где MEXC дешевле. В режиме liquidity рукав проверяет свой список, а не общую восьмёрку рынка. Пара вне списка, в том числе из скана ликвидности, не покупается. Цикл входов обрывается через 40 секунд. В режиме ликвидности за цикл проверяется не больше 8 пар, по одной.

## Входы

Новые входы выключены, пока нет ровно `SPOT_ENTRIES=1`. Отказ стоит на самой покупке, не только на обходе списка. Уже открытая позиция при этом продаётся по своим правилам. Последний прогон 14 пар после комиссии и спреда 30 bps не обыграл простой отказ от сделки. Плюс одного куска ленты стакан и лимитную продажу не включает.

Цикл с пустым списком, повтором пары, долей вне кассы, слотами вне 1..14 или RSI вне 1..99 ордер не начинает. Доля покупки не больше всей кассы. RSI от 1 до 99. Свеча с ценой не больше нуля сигнал на вход не даёт. RSI считает только закрытые свечи: последняя, ещё открытая, в сигнал не входит. RSI ликвидности тоже не смотрит на незакрытую свечу. Свеча с невозможным диапазоном, нулевым объёмом, другой длиной или временем назад в сигнал не идёт. Свечи не могут наезжать по времени. Отклонение полосы Боллинджера целое, без двоичной дроби.

Покупка не уходит, если верх стакана шире `SPOT_SPREAD_BPS` (по умолчанию 30). Это один запрос лучшей цены, не сокет. Уровень без объёма — пустая книга. Пустая сторона стакана и перекрёстный стакан отказывают. Одна и та же цена в стакане дважды не суммируется. Стакан без номера обновления не используется. Бумажная покупка записывается по аску того же снимка, по которому проверен спред. Если следующий снимок показывает аск выше уже проверенного, покупка не уходит. Повторный ask ниже проверенного больше чем на 15% покупку не открывает. Покупка не ставится, если ask ушёл от закрытой свечи больше чем на 15%. Последняя сделка тикера исполнением не считается.

Повторная покупка пары, которая уже в книге, не отправляется. Сумма живой покупки не больше кассы этой книги и не больше свободного USDT. Заблокированный USDT в заявку не идёт. Если свободного меньше шага пары, ордер не отправляется.

### Правило RSI

Взято из старой папки `Торговля`: вход при RSI ниже 35; подтверждение, которое в старом коде было написано и не вызывалось, — нижняя полоса Боллинджера или свежее пересечение MACD вверх. Выход: стоп 3.5%, тейк 7%, трейлинг с +3% и откат 2%.

Не взято: ключи из исходников, Flask-панель, фьючерсы, кросс-чейн «мост», функция с именем machine learning (это две скользящие средние). Сетка и усреднение сюда не входят.

### Правило ликвидности

Смотрит пары USDT, у которых за сутки объём уже заметен и ход от +0.5% до +12%. В скане суток нет процента — пара не считается плоской. Повтор имени берёт больший объём. Строчные буквы не проходят. Покупка только если последняя закрытая 5-минутная свеча дала объём хотя бы вдвое выше медианы предыдущих и закрылась в верхней части диапазона, а в стакане нотионал покупок больше продаж. Чётная медиана объёма берёт верхнюю середину. Цель продажи ставится на +2.5% сразу. Если при плюсе заявки на продажу становятся больше покупок, позиция закрывается раньше. Стоп 1.5%.

## Сверка цен

Покупка на MEXC сверяется с живыми ценами Binance, Bybit и OKX. Ордера на те биржи не отправляются. В логе строка `oracle`: цена MEXC, три другие, `lag_bps` и `width_bps`. Положительный `lag_bps` значит, что MEXC дороже медианы остальных. Чётное число цен оракула берёт нижнюю середину, чтобы ширина не занижалась. Чужое имя на Binance, Bybit или OKX в сверку не входит.

Покупка не проходит, если другой площадки нет, если разброс шире 30 bps, или если MEXC впереди больше чем на 15 bps. Прибыльная позиция закрывается раньше с причиной `mexc_ahead`, когда MEXC впереди хотя бы на 15 bps и прибыль уже от 30 bps. Стоп без ответа оракула всё равно срабатывает. Ранний выход по стене заявок или по оракулу сверяется с новым стаканом и новыми ценами. Оракул сравнивает аск входа с другими площадками.

Режим `liquidity` дополнительно ставит целочисленную оценку. Это не нейросеть. Горячая оценка может считаться в `native/` (Rust); пока dll нет, считает Python и пишет это в лог.

## Выходы

Нулевой стоп, тейк или трейл сделку не закрывает: ровная цена не считается выходом. Бумажная продажа и оценка выхода — по биду. Выход сверяется второй раз: если этот bid уже не даёт причину продажи, заявка не уходит. Перед самой заявкой книга читается ещё раз. Цена выхода не больше нуля или дальше чем в пять раз от пика позицию не продаёт и пик не двигает. Новые входы в этом цикле тоже закрыты. Дыра сквозь стоп, которая меньше этого предела, продажу не отменяет. Пик позиции не ниже цены входа и поднимается только вверх.

Количество режется вниз до шага лота. Остаток меньше шага в заявку не ставится и остаётся в позиции. Его бид всё равно входит в оценку книги; без этого бида новый вход не открывается. Бумажная продажа режется тем же шагом. Он не занимает место под новую сделку. Заблокированная часть остаётся в книге, заявка не создаётся. Бумажная продажа с чужим именем монеты, размером больше позиции или нулевой суммой монеты не списывает. Если правила пары прочитать не удалось, бумажная продажа позицию не закрывает. Продажа пишется только на свою пару и не выше отправленного количества монеты. Продажа с нулевой суммой монеты не списывает. Продажа не использует номер клиента или номер ордера, который уже стоит на позиции. Вторая строка той же пары в книгу не пишется, а продажа при двух таких строках не списывает первую наугад.

Живая продажа уходит только когда свободна вся отправляемая монета. Продажа в живом режиме зачисляет только `cummulativeQuoteQty` из ответа; без него позиция остаётся. Если биржа исполнила меньше, чем лежало в книге, остаток в книге сохраняется. Неполная продажа не закрывается, если остаток монеты не равен размеру позиции на момент отправки минус уже записанный объём. Полная продажа отправленного размера может оставить позицию пустой.

После выхода по стопу новые входы в этой книге закрыты на `SPOT_STOP_COOLDOWN_SEC` (по умолчанию 900 секунд). Тейк и трейлинг паузу не ставят. Выход во время паузы остаётся. Три стопа одной пары за сутки запирают эту пару на `SPOT_STOP_LOCK_SEC` (по умолчанию 14400 секунд). Остальные пары книги не запираются. Часы сверки и пауза после стопа берут целые секунды.

### Обрыв связи

Если книгу не удалось прочитать дольше двух циклов и не меньше трёх минут, а бид уже не покрывает цену монеты с комиссией, продажа не уходит. Этот запрет записывается и держится, пока бид снова не покроет цену. Пока связь обычная и книга свежая, стоп продаёт как раньше. Метка времени из будущего считается таким же обрывом. Первая цена после обрыва продажу не открывает и пик по ней не поднимается. Если подтверждающая цена снова ниже себестоимости или её прочитать нельзя, заявка не уходит и запрет возвращается. Обрыв сети не останавливает процесс: следующий цикл ждёт и читает книгу снова. Это не обещание, что цена вернётся, и не рыночная продажа «в ноль» сразу после обрыва.

## Лимиты входов

Если реализованный результат дня вместе с открытым убытком просел на `SPOT_DAILY_LOSS_BPS` (по умолчанию 500, это 5% утренней наличности книги), новые входы в этой книге до завтра не открываются. Сутки считаются по UTC. В первый цикл нового дня утренняя наличность фиксируется до выходов этого цикла: и уже открытый убыток, и убыток, закрытый в этом же цикле, входят в дневной лимит. Если утром наличности не было, закрытый в этот день убыток всё равно запрещает новый вход. Плюс по открытой позиции этот порог не уменьшает. Выходы при этом продолжаются.

Просадка считается от пика кассы с открытыми монетами по `SPOT_DRAWDOWN_BPS` (по умолчанию 1000, это 10%). Монета в этой оценке — бид после комиссии тейкера пары, не голая сумма. Если эту комиссию прочитать нельзя, новый вход не открывается. Если цену открытой позиции прочитать не удалось, новый вход не открывается. Отрицательная оценка кассы новые входы закрывает. Пик кассы поднимается только вверх.

## Фильтры пары

Покупка читает `exchangeInfo` пары. Книга, последняя цена и правила пары принимаются только если в ответе имя этой пары. Две строки правил одной пары не кэшируются. Заявка без пары, номера или размера не уходит.

Комиссия берётся из `takerCommission` этой пары и округляется вверх. Нулевая комиссия с биржи остаётся нулевой и в медиану прогона не идёт. `SPOT_TAKER_BPS` — запас для бумажного счёта, когда своей комиссии пары ещё нет. Лот округляется до `baseSizePrecision`. `quoteAmountPrecisionMarket` — минимальный шаг суммы рыночной заявки, не число знаков: на USDT-парах 13 октября 2026 это `"1"`, то есть 1 USDT. Шаг цены берётся из `quotePrecision`. Нулевой шаг лота, нулевой минимум суммы и нулевой потолок суммы не становятся разрешением торговать. Булево значение не считается суммой, шагом лота, комиссией или вкладом в рукава. Пара, у которой один шаг цены шире стопа, в сделку и в медиану не идёт.

Пара без типа MARKET, с пустым списком типов, со статусом не «торгуется», с меткой ST или с плитой Assessment в покупку не идёт. Имя монеты для продажи берётся из `baseAsset` и должно совпадать с парой. Покупка разрешена только если `tradeSideType` равен 1: пару можно и купить, и продать. Пустое поле и режим «только покупка» сделку не открывают. Уже открытая позиция при этом продаётся.

## Живая заявка

Если часы компьютера ушли от часов MEXC больше чем на 2 секунды или время биржи прочитать не удалось, живые заявки в этом цикле не отправляются: окно подписи 5 секунд. Позиция при этом остаётся. Время подписи берётся из целых наносекунд. Нулевая книга и время сервера не из целого числа отказывают. Два номера заявки в одну наносекунду не совпадают.

Перед живой заявкой её клиентский номер пишется в книгу. Клиентский номер — от 1 до 32 символов из букв, цифр, подчёркивания и дефиса, и только на USDT-паре. Номер ордера биржи, если он есть, состоит из цифр. Номер сделки и номер ордера в строке сделки — цифры, и в строке должно быть имя пары. Пока номер заявки не закрыт, вторая заявка, в том числе по другой монете, не отправляется и номер не затирается. Запись нового номера поверх уже открытого отвергается. Пока в другой книге того же счёта висит номер заявки, эта книга тоже не отправляет ордер. Покупка не пишется на строку с тем же номером клиента, но другой парой, и пустой номер клиента позицию не двигает.

Если процесс оборвался после отправки, следующий цикл читает ордер по этому номеру и записывает сделку один раз. Ответ с кодом ошибки биржи не считается заявкой, даже если HTTP-статус 200. Ответ другого типа или с объёмом больше отправленного в книгу не пишется. Чужой ответ — другая пара, сторона или номер — в книгу не пишется. Ответ живой заявки с чужим клиентским номером в книгу не пишется. Два разных клиентских номера в одном ответе заявку не подтверждают. Список сделок читается как список, а не как объект заявки. Первый номер ордера биржи закрепляется: следующий ответ с другим номером ту же заявку не закрывает.

Пока чтение заявки говорит, что её нет, номер не стирается. Текст «does not exist» без заявки номер не снимает. Если биржа три цикла подряд говорит, что заявки нет, и в книгу по ней ещё ничего не записано, номер снимается. Ошибка самой отправки номер не стирает: заявка могла уже быть принята. Ненулевое количество, которое не читается, или нулевая сумма при таком количестве тоже номер не снимают. Нулевое количество в любой десятичной записи — пустой филл, а не снятие номера. Номер, который биржа уже подтвердила, не снимается ответом «заявки нет». Отмена, в которой биржа показывает ноль, не стирает уже записанное исполнение. Отмена без исполнения снимает ожидание. Отмена, в которой часть уже исполнилась, записывает только эту часть: у продажи остаток монеты остаётся в позиции. Если проверка остатка не проходит, номер заявки не снимается. Одна такая ошибка номер не стирает.

Частично исполненная живая заявка пишется в книгу по факту и не продаётся, пока биржа её не закрыла. Повтор того же объёма кассу второй раз не двигает. Повторное исполнение покупки не держит пик от более дорогого частичного объёма, если этот пик не поднимал рынок. Повтор того же исполнения покупки не закрывает заявку, если монеты с этим номером в книге уже нет, их количество или сумма не равны уже списанным, или цена входа не равна котировке, делённой на эти монеты. Пик такой покупки не может быть ниже цены входа. Живая покупка списывает сумму из ответа, а не запрошенную. Цена входа живой покупки — уплаченная котировка, делённая на полученную монету, а не тикер до заявки. Восстановленная покупка ставит цену входа по монете, которая осталась после комиссии, а не по полному объёму заявки. Покупка пишется только на свой номер, свою USDT-пару и не выше запрошенной суммы.

Если комиссию заявки прочитать не удалось, запись не закрывается и вторая заявка не отправляется. Комиссия USDT берётся из `myTrades` по номеру этой заявки, если её не было в ответе ордера. Если в списке сделок нет строки этого ордера, комиссия не считается нулём. Если страница сделок заявки заполнена до лимита, комиссия считается непрочитанной. Сумма строк должна совпасть с объёмом заявки, иначе комиссия неполная и заявка не закрывается. Строка без своего номера, повтор того же номера или чужая сторона заявку не закрывают. У строки сделки должна быть положительная цена, и цена на количество должна попасть в сумму строки с точностью до одной миллионной USDT.

Комиссия, снятая купленной монетой, уменьшает позицию. Комиссия в третьей монете заявку не закрывает. Комиссия, которая не помещается в кассу или в сумму сделки, не обрезается: заявка остаётся открытой. Записанная комиссия не больше записанной суммы сделки. Комиссия в ответе заявки не в USDT и не равная списку сделок не считается нулём. Если на том же объёме комиссия стала больше, разница списывается; если стала меньше, заявка не закрывается. Если ответ продажи уже назвал комиссию, она должна совпасть со списком сделок. Если комиссия купленной монетой на том же объёме стала больше, позиция уменьшается на разницу; если стала меньше, заявка не закрывается. Живой ордер биржевую комиссию сам не дописывает второй раз.

В живом режиме перед новым входом книга сверяется с `GET /api/v3/account`: количество монеты должно совпасть, лишняя монета на счёте останавливает входы. Монета другого рукава на том же счёте лишней не считается: в сумму входят все три книги. USDT в этой сверке не сравнивается. Строка баланса без актива или не объектом не считается пустым счётом. Отрицательный баланс отвергается. Имя актива приводится к верхнему регистру. Один и тот же актив в счёте не складывается. Несовпадение или ошибка чтения счёта не открывает новую позицию. Выходы продолжаются.

Нечисловая цена свечи, стакана или ответа заявки остаётся ошибкой этой пары и не останавливает остальные рукава.

## Лимит биржи и сеть

HTTP 403, 418 и 429, и тот же код в теле ответа при HTTP 200, останавливают остаток этого цикла. Книга записывается, следующий рукав в этом проходе не стартует. Следующий цикл ждёт заголовок Retry-After, но не меньше двух минут, если заголовок не разобран, и не дольше трёх суток. Повтор внутри цикла не крутится. Ответ 429 или 418 останавливает остаток скана. Тот же ответ на одном рукаве не запускает следующий рукав в этом проходе.

Публичный и подписанный запрос, и цены других площадок, не идут по редиректу. Запросы к MEXC, Binance, Bybit и OKX не идут через прокси из окружения. Битый файл котировок не обрывает цикл и не смешивается с новой строкой.

## Страница наблюдения

Только `127.0.0.1:19280` (`SPOT_OPS_PORT`). Порт страницы только из цифр. Порты `18180–18182` она не занимает. Страница читает книги, последние цены сверки, сделки и журнал. Ордера с неё не отправляются, ключи на неё не попадают. Запись любым методом отказывает. Бот с флагом `--ops` поднимает ту же страницу внутри процесса. Отдельный просмотр: `python -m spotbot.ops_main`. Пока страница уже слушает этот порт, второй процесс на него не садится.

Ops показывает возраст последнего завершённого цикла. Битый файл книги, пульса или журнала не гасит страницу. Цена не из целого числа показывается как нечитаемая.

## Прогон по свечам

`python -m spotbot.replay_main` печатает результат RSI и свечную половину правила ликвидности на раннем и позднем куске одной ленты. Параметры на кусках одни и те же и на ленте не подбирались. Покупка и продажа исполняются по закрытию следующей свечи, не по свече сигнала. Покупка и продажа в прогоне хуже закрытия на 30 bps. Стоп, тейк и трейл видят эту же цену, а не сырое закрытие. Это тот же потолок спреда, который живая покупка уже отвергает, а не исторический спред ленты.

«Просто держать» покупает ту же долю кассы, что и правило. Пока позиция открыта, её оценка печатается отдельно и из удержания не вычитается. Медиана — это закрытые сделки плюс оценка ещё открытой позиции. Если цену открытой позиции посчитать нельзя, пара в медиану не идёт и ноль не печатается. Пара с комиссией 0 в медиану не идёт. Вторая строка прогона не включает стакан и оракул, поэтому это не живое правило. Плюс одного куска не включает стакан и не ставит лимитную продажу.

## Переменные

Пустые ключи в `.env.example`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MEXC_API_KEY`, `MEXC_API_SECRET` | пусто | Нужны только для живых ордеров |
| `SPOT_SYMBOLS` | BTC, ETH, SOL | Список бумажного цикла без `--sleeves` |
| `SPOT_PAPER_CASH_USDT` | 1000 | Стартовая бумажная касса |
| `SPOT_INTERVAL_SEC` | 60 | Пауза между циклами |
| `SPOT_LIVE` | 0 | Живые ордера только вместе с `--live` и значением `1` |
| `SPOT_ENTRIES` | 0 | Новые входы только при значении `1` |
| `SPOT_TAKER_BPS` | 5 | Запасная комиссия, если у пары своей ещё нет |
| `SPOT_DAILY_LOSS_BPS` | 500 | Дневной предел убытка, 5% |
| `SPOT_DRAWDOWN_BPS` | 1000 | Просадка от пика кассы, 10% |
| `SPOT_STOP_COOLDOWN_SEC` | 900 | Пауза входов после стопа |
| `SPOT_STOP_LOCK_COUNT` | 3 | Сколько стопов одной пары запирают её |
| `SPOT_STOP_LOCK_SEC` | 14400 | На сколько секунд пара запирается |
| `SPOT_SPREAD_BPS` | 30 | Шире этого спреда покупка не идёт |
| `SPOT_OPS_PORT` | 19280 | Страница наблюдения, только localhost |
