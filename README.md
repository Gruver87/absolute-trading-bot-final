# Спот-бот MEXC

Бумажный спот по умолчанию. Ордер на MEXC уходит только если в `.env` стоит ровно `SPOT_LIVE=1` и процесс запущен с `--live`. Это не обещание прибыли и не прогноз. Цепь DUP бот не импортирует. Лицензия — все права у автора, это не MIT.

Повтор без `--once` крутит цикл раз в `SPOT_INTERVAL_SEC` (по умолчанию 60 секунд).

## Решение

Покупки выключены. На одной ленте, одними параметрами, после комиссии и 30 bps обе половины RSI и свечная половина ликвидности ниже нуля. Лучшая цена после входа у стоп-сделок была меньше круга сделки. Пока это так, цикл продаёт только уже открытую монету и новых покупок не делает. Новое правило имеет смысл мерить только на ленте, которую не смотрели до записи правила. Входы открываются, когда обе половины обоих правил на ней выше нуля. Стакан по сокету, стоящая лимитка, сетка, усреднение, шорт и фьючерс в этот бот не входят.

## Деньги

Суммы котировки хранятся целыми: `1 USDT = 1_000_000`. Float и булево значение на этом пути отвергаются. Цена одной монеты хранится в `1e-12` USDT, касса по-прежнему в миллионных: так стоп 3.5% существует и на дешёвой монете. Все пороги ниже — в bps, `100 bps = 1%`.

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
.\.venv\Scripts\python -m spotbot --once --sleeves
```

| Команда | Что делает |
|---|---|
| `python -m spotbot --once` | Один бумажный цикл RSI |
| `python -m spotbot --mode liquidity --once` | Один цикл ликвидности, отдельная книга |
| `python -m spotbot --sleeves --once` | Три рукава, у каждого своя книга |
| `python -m spotbot.ops_main` | Только страница наблюдения |
| `python -m spotbot.replay_main --symbol BTCUSDT` | Прогон правила по свечам, без ордеров |
| `python -m pytest tests/test_logic.py -q` | Проверка правил. Корень проекта на пути импорта |

Ключи MEXC в исходниках не лежат. Токен Telegram процесс не загружает. Публичные свечи работают без ключей.

## Счета

По умолчанию бумажный счёт в `data/paper/book.json`. Живой счёт пишется в `data/live/` и бумажную книгу не читает. Режим `liquidity` пишет в `data/paper/book_liquidity.json` и с RSI не смешивается.

Книга заменяется целиком. Оборванная запись предыдущий файл не стирает. Файл, который при открытии был бы отвергнут, на диск не пишется. Битая книга не открывается и не затирается. Книга без кассы и позиция без поля не открываются. Книга с отрицательной кассой, двумя строками одной пары или повтором номера клиента не открывается. День охраны не из даты или из будущего книгу не открывает. Пауза после стопа, записанная не как время, книгу не открывает. Пара в книге только из заглавных букв и цифр и оканчивается на `USDT`.

## Рукава

Устойчивые: BTC, ETH. Альты: SOL, XRP, ADA, AVAX, LINK, DOT. Мемы: DOGE, SHIB, PEPE, FLOKI, BONK, WIF. Котировка — USDT. Список пар в настройке не повторяется. Одна и та же пара не входит в два рукава. Слотов от 1 до 14. В каждой книге одновременно одна монета, на всю сумму этой книги.

Прибыль и убыток остаются в своей книге. Новый вклад с основного баланса делится на три и добавляется сверху. 100 USDT делятся как 33.333334 + 33.333333 + 33.333333, чтобы не потерять satoshi. Уменьшить основной баланс и забрать деньги из книг бот отказывается. Казна с суммой не из целого числа, с минусом или с битым файлом деньги не добавляет. Новый вклад пишется вместе с отметкой суммы: повтор после обрыва ту же сумму второй раз не добавляет.

Цикл читает весь список рукава и из прошедших фильтр берёт ту, где MEXC дешевле. В режиме liquidity рукав проверяет свой список, а не общую восьмёрку рынка. Пара вне списка, в том числе из скана ликвидности, не покупается. Цикл входов обрывается через 40 секунд. В режиме ликвидности за цикл проверяется не больше 8 пар, по одной.

## Входы

Новые входы выключены. `SPOT_ENTRIES=1` процесс не включает: последний прогон 14 пар после комиссии и спреда 30 bps не обыграл простой отказ от сделки. Уже открытая позиция при этом продаётся по своим правилам. Плюс одного куска ленты стакан и лимитную продажу не включает.

Цикл с пустым списком, повтором пары, долей вне кассы, слотами вне 1..14 или RSI вне 1..99 ордер не начинает. Доля покупки не больше всей кассы. RSI от 1 до 99. Свеча с ценой не больше нуля сигнал на вход не даёт. RSI считает только закрытые свечи: последняя, ещё открытая, в сигнал не входит. RSI ликвидности тоже не смотрит на незакрытую свечу. Свеча с невозможным диапазоном, нулевым объёмом, другой длиной или временем назад в сигнал не идёт. Свечи не могут наезжать по времени. Отклонение полосы Боллинджера целое, без двоичной дроби.

Покупка не уходит, если верх стакана шире `SPOT_SPREAD_BPS` (по умолчанию 30). Это один запрос лучшей цены, не сокет. Уровень без объёма — пустая книга. Пустая сторона стакана и перекрёстный стакан отказывают. Одна и та же цена в стакане дважды не суммируется. Стакан без номера обновления не используется. Бумажная покупка записывается по аску того же снимка, по которому проверен спред. Если следующий снимок показывает аск выше уже проверенного, покупка не уходит. Перед самой заявкой нотионал у касания читается снова, и более тяжёлая продажа покупку отменяет. Повторный ask ниже проверенного больше чем на 15% покупку не открывает. Покупка не ставится, если ask ушёл от закрытой свечи больше чем на 15%. Последняя сделка тикера исполнением не считается.

Повторная покупка пары, которая уже в книге, не отправляется. Сумма живой покупки не больше кассы этой книги и не больше свободного USDT. Заблокированный USDT в заявку не идёт. Если свободного меньше шага пары, ордер не отправляется.

### Правило RSI

Взято из старой папки `Торговля`: вход при RSI ниже 35 на закрытии под нижней полосой. Покупка на следующей свече, когда закрытие уже вернулось выше этой полосы и выше предыдущего закрытия. Если к заявке аск снова под этой полосой или не выше предыдущего закрытия, покупка не уходит. Живой вход ещё требует, чтобы у касания нотионал заявок на покупку был больше заявок на продажу. Пока закрытие ещё под полосой, это пробой, не разворот, и вход не берётся. Свежее пересечение MACD вниз вход блокирует. Выход: стоп 3.5%, тейк 7%, трейлинг с +3% и откат 2%.

Не взято: ключи из исходников, Flask-панель, фьючерсы, кросс-чейн «мост», функция с именем machine learning (это две скользящие средние). Сетка и усреднение сюда не входят.

### Правило ликвидности

Смотрит пары USDT, у которых за сутки объём уже заметен и ход от +0.5% до +12%. В скане суток нет процента — пара не считается плоской. Повтор имени берёт больший объём. Строчные буквы не проходят. Покупка только если последняя закрытая 5-минутная свеча дала объём хотя бы вдвое выше медианы предыдущих и закрылась в верхней части диапазона, а в стакане нотионал покупок больше продаж. Чётная медиана объёма берёт верхнюю середину. Цель продажи ставится на +2.5% сразу. Если при плюсе заявки на продажу становятся больше покупок, позиция закрывается раньше. Стоп 1.5%.

## Сверка цен

Покупка на MEXC сверяется с живыми ценами Binance, Bybit и OKX. Ордера на те биржи не отправляются. В логе строка `oracle`: цена MEXC, три другие, `lag_bps` и `width_bps`. Положительный `lag_bps` значит, что MEXC дороже медианы остальных. Чётное число цен оракула берёт нижнюю середину, чтобы ширина не занижалась. Чужое имя на Binance, Bybit или OKX в сверку не входит.

Покупка не проходит, если другой площадки нет, если разброс шире 30 bps, или если MEXC впереди больше чем на 15 bps. Прибыльная позиция закрывается раньше с причиной `mexc_ahead`, когда MEXC впереди хотя бы на 15 bps и прибыль уже от 30 bps. Стоп без ответа оракула всё равно срабатывает. Ранний выход по стене заявок или по оракулу сверяется с новым стаканом и новыми ценами. Оракул сравнивает аск входа с другими площадками.

Режим `liquidity` дополнительно ставит целочисленную оценку. Это не нейросеть. Горячая оценка может считаться в `native/` (Rust); пока dll нет, считает Python и пишет это в лог.

## Выходы

Нулевой стоп, тейк или трейл сделку не закрывает: ровная цена не считается выходом. Бумажная продажа и оценка выхода — по биду. Выход сверяется второй раз: если этот bid уже не даёт причину продажи, заявка не уходит. Перед самой заявкой книга читается ещё раз. Цена выхода не больше нуля или дальше чем в пять раз от пика позицию не продаёт и пик не двигает. Новые входы в этом цикле тоже закрыты. Дыра сквозь стоп, которая меньше этого предела, продажу не отменяет. Пик позиции не ниже цены входа и поднимается только вверх.

Количество режется вниз до шага лота. Остаток меньше шага в заявку не ставится и остаётся в позиции. Его бид всё равно входит в оценку книги; без этого бида новый вход не открывается. Бумажная продажа режется тем же шагом. Он не занимает место под новую сделку. Заблокированная часть остаётся в книге, заявка не создаётся. Бумажная продажа с чужим именем монеты, размером больше позиции или нулевой суммой монеты не списывает. Если правила пары прочитать не удалось, бумажная продажа позицию не закрывает. Продажа пишется только на свою пару и не выше отправленного количества монеты. Продажа с нулевой суммой монеты не списывает. Продажа не использует номер клиента или номер ордера, который уже стоит на позиции. Вторая строка той же пары в книгу не пишется, а продажа при двух таких строках не списывает первую наугад.

Живая продажа уходит только когда свободна вся отправляемая монета. Продажа в живом режиме зачисляет только `cummulativeQuoteQty` из ответа; без него позиция остаётся. Если биржа исполнила меньше, чем лежало в книге, остаток в книге сохраняется. Неполная продажа не закрывается, если остаток монеты не равен размеру позиции на момент отправки минус уже записанный объём. Полная продажа отправленного размера может оставить позицию пустой.

После выхода по стопу новые входы в этой книге закрыты на `SPOT_STOP_COOLDOWN_SEC` (по умолчанию 900 секунд). Тейк и трейлинг паузу не ставят. Цена уже сквозь стоп считается стопом, и пауза ставится. Выход во время паузы остаётся. Три стопа одной пары за сутки запирают эту пару на `SPOT_STOP_LOCK_SEC` (по умолчанию 14400 секунд). Остальные пары книги не запираются. Часы сверки и пауза после стопа берут целые секунды.

### Обрыв связи

Если книгу не удалось прочитать дольше двух циклов и не меньше трёх минут, а бид уже не покрывает цену монеты с комиссией, продажа не уходит. Этот запрет записывается и держится, пока бид снова не покроет цену. Пока связь обычная и книга свежая, стоп продаёт как раньше. Метка времени из будущего считается таким же обрывом. Первая цена после обрыва продажу не открывает и пик по ней не поднимается. Фитиль, пока запрет держится, пик тоже не поднимает. Если подтверждающая цена снова ниже себестоимости или её прочитать нельзя, заявка не уходит и запрет возвращается. Обрыв сети не останавливает процесс: следующий цикл ждёт и читает книгу снова. Битая книга соседнего рукава новые входы закрывает и процесс не останавливает; продажа этой книги при этом идёт. Сессия биржи и сессия сверки печенье не хранят. Ответ больше 8 МБ не разбирается. Нулевой объём монеты в свече сигнал не даёт. Запись с показателем степени не считается нулём. Булево значение не считается ценой прыжка, шагом цены или ценой исполненного объёма. Метка пульса из будущего на странице не показывается как только что. Журнал сделок читается с конца, а не целиком. Запись сделки тоже читает только хвост журнала и не роняет цикл, если файл раздут. Книга или казна больше 1 МБ не открывается и файл не затирается. Журнал страницы тоже читается с конца. Булево значение не считается прибылью, просадкой, спредом или кассой. Оно также не считается часами биржи, ценой другой площадки, долей покупки, сигналом входа или номером заявки. Оно не считается объёмом свечи, стороной стакана, оценкой выхода, открытым убытком, свободной монетой или числом в настройке цикла. Оно не стирает номер заявки, не сверяет объём, не проходит как комиссия и кассу не двигает. Книга с таким числом на диск не пишется. Дробь не считается комиссией, ценой, периодом индикатора или шагом тика. Дробь также не списывает кассу, не сверяет объём, не стирает номер заявки и стоп по ней не ставится. На провод она не уходит, заявку не запоминает и оценку кассы не даёт. Дробные часы биржи сверенными не считаются, дробный предел свечей в запрос не уходит, а номер заявки из числа нашим не признаётся. Дробный код ответа успехом не считается, дробный баланс с книгой не сходится, и имя пары из числа не принимается. Номер сделки из числа со строковым не сходится, дробная прибыль выход не открывает, а дробный статус заявки исполненным не считается. Код `-20110` неизвестным ордером не считается. Статус пары, сторона и тип заявки принимаются только текстом. Нулевой шаг котировки, если он указан, пару закрывает и не подменяется другим полем. Метка стопа из булева значения книгу не открывает. Номер заявки, имя пары, сторона, книга режима и день охраны в файле принимаются только текстом: число не превращается в номер. Нулевая сумма исполнения, если поле указано, вторым именем того же поля не подменяется. Имя монеты в балансе и имя комиссии принимаются только текстом. Запрос свечей, стакана или сделок с нетекстовой парой на биржу не уходит. Запрос без пары USDT тоже не уходит, а флаг режима, который не булев, бумажную кассу в живую папку не переносит. Такой же флаг живой торг не включает. Ключ с переносом строки не читается. Причина позиции, которая не текст, кассу не списывает. Подпись уходит только методом GET или POST на путь `/api/v3/` и только с текстовыми полями. Длинный Retry-After неизвестной паузой считается, а не огромным числом. Порт страницы и числа настройки из длинной строки цифр не читаются. Режим книги принимается только как бумага или живой счёт. Сумма, цена и ключ длиннее разумного потолка не читаются и в запрос не уходят. Произведение двух чисел, если оно выше потолка, покупкой, ценой входа или комиссией не становится. Комиссия выше 100 bps не считается. Дробный объём сигнал не даёт. Свечей больше 1000 и уровней стакана больше 5000 разбор не продолжает. Пауза после стопа из булева значения не сжимается до одной секунды. Порог подъёма объёма, дневной стоп, оценка ликвидности, предел прыжка цены и очередь отставания из булева значения тоже не работают. Файл книги или котировок больше 1 МБ на страницу не читается. Цена на потолке чужой площадкой не считается, оценка входа число шире разрядности модуля не принимает, а суточный список длиннее 20000 строк не разбирается. Вклад в рукав выше потолка кассу не двигает, книга больше чем из восьми позиций не открывается, а чужой тикер из нескольких строк ценой не считается. Заявка размером на потолке не уходит, выход шире 100% в цикл не пускается, а сверка из больше чем восьми цен шириной не считается. Ожидание ответа дольше 30 секунд не ставится, причина позиции длиннее 80 знаков кассу не списывает, а сверка объёма на потолке исполнением не считается. Продажа, которая подняла бы кассу выше потолка, монету не списывает. Пауза после стопа длиннее суток не ставится. Цена на потолке в журнал и на страницу пишется как нечитаемая и цикл не роняет. Незавершённый раздел вклада дописывается один раз, а ошибка денег останавливает проход и не гасит процесс. Лимит запросов к часам биржи книгу всё равно записывает, и утренний штамп кассы не теряется. Незавершённый ответ биржи, если заявка уже принята, оставляет её номер в книге, и три пустых ответа её не стирают. Размер на потолке не округляется в заявку, свеча с невозможным временем не читается, счётчик пропуска больше тысячи книгу не открывает, а длинное имя пульса на страницу не пишется. Длинная строка свечи или уровень стакана не разбирается, комиссия в чужом или слишком большом имени монеты не считается, а страница не разворачивает слишком глубокий или широкий файл. Шаг лота на потолке пару закрывает, длинное имя пластины или типа заявки пару не открывает, а строка журнала длиннее экрана на странице обрезается. Остаток на потолке и имя, которое не пара USDT, сверку не проходят. Длинный статус заявки исполнением не считается, а текст сетевой ошибки и чужое значение в журнале целиком не пишутся. Номер заявки длиннее тридцати двух цифр не читается, имя пары в текст ошибки не копируется, а длинная котировка на страницу целиком не попадает. Полный диск не называется чужим процессом, длинный адрес страницы не читается, а слишком широкий список пар на биржу не запрашивается. Файл больше мегабайта книгу не заменяет, больше тысячи свечей не запрашивается, а число на потолке и дробь на страницу не попадают. Длинный текст книги и старая цена, которая после масштаба уходит за потолок, файл не открывают, а длинная строка ошибки в журнал целиком не пишется. Слишком глубокий файл не открывается, длинное имя комиссии не читается, а больше восьми открытых позиций убыток не считает. Отрицательная комиссия бумажную сделку не проводит, больше восьми позиций биржу не спрашивает, утренний штамп потолок не копирует, а слишком широкая строка биржи не читается. Слишком широкий ответ цены, стакана, счёта или времени не читается, длинный список в строке пары не читается, а имя сигнала длиннее 32 символов входа не даёт. Слишком широкая строка суточного тикера, чужой сделки или чужой биржи не читается, цена вне свечи сигналом не считается, длинная строка журнала не хранится, а метка позже 2100 года замок пары не ставит. Слишком длинная команда не запускается, вложенная строка пары не читается, длинное имя соседней книги в текст ошибки не копируется, а длинный текст ошибки биржи в журнал целиком не пишется. Слишком широкая касса и открытый дележ не читаются, слишком длинная строка журнала на страницу не попадает, а имя книги длиннее 32 символов в журнал не пишется. Слишком большой журнал процесс не открывает, порог RSI шире 500 входа не даёт, а ответ страницы больше мегабайта не отправляется. Слишком длинный день охраны не читается, слишком мелкий масштаб суммы не считается, а длинный список исполнений в ответе заявки не читается. Счётчик стопов шире восьми всё равно запирает пару, слишком длинная пауза после лимита не длиннее суток, а чужой код HTTP числом не пишется. Каталог книгой не читается, покупка без запрошенной суммы и продажа без монеты исполнением не считаются, а позиция шире 16 полей на странице не читается. Файл каталогом кассы не считается, пауза цикла не длиннее суток, а слишком большой файл библиотеки не загружается. Флаг входов процесс не включает: измеренное правило после комиссии и спреда в минусе. Сигнальная линия MACD считается и ниже нуля, иначе подтверждение на падении не срабатывает. Сторона спота числом 1 читается как двусторонняя торговля, булево и дробь — нет. Свеча, у которой время закрытия равно времени открытия плюс интервал, читается. Пара без шага лота из медианы выходит, остальные пары считаются. Флаг входов процесс не останавливает: входы остаются выключены, продажа открытой позиции идёт. Поздний кусок прогона видит свечи до разреза и не берёт ещё открытую свечу. Исполнение в прогоне — открытие следующей свечи, как рыночная заявка сразу после сигнала. Свеча с нулевым объёмом из ленты выходит, соседние свечи остаются. Запрос длиннее 500 свечей дочитывает предыдущую страницу: биржа одну страницу режет на 500. После стопа прогон ждёт 15 минут, третий стоп за сутки запирает пару на 4 часа. Продажа в прогоне идёт по цене, которая уже сработала, а не по следующей свече. Стоп проверяется и на свече покупки. Цикл RSI читает цену закрытия свечи, а не объём в USDT. Сигнал RSI в цикле и в прогоне смотрит последние 79 закрытых свечей: запрос 80 без ещё открытой. Вход RSI берётся на возврате закрытия над нижней полосой, не пока закрытие ещё под ней. Возврат, у которого закрытие не выше предыдущего, входом не считается. Свеча с прыжком закрытия больше 15% остаётся в ленте: вход на ней не берётся, стоп её видит. В стене стакана считаются заявки не дальше 30 bps от лучшей цены: более дальний уровень следующей сделкой не бьётся. Вход RSI вживую не берётся, если у касания продажа не меньше покупки; в свечном прогоне этого стакана нет, и измеренный минус из-за этого не становится плюсом. То же сравнение читается ещё раз прямо перед заявкой. Аск, который успел вернуться под нижнюю полосу, покупкой не становится. Прогон продаёт по первому минутному закрытию, где выход уже виден. Медиана печатается и по каждой книге рукава отдельно, тем же правилом. Продажа сквозь стоп считается стопом, даже если до этого верх уже включил трейл: пауза после стопа её учитывает. Открытие следующей свечи дальше чем на 15% от закрытия сигнала в прогоне не покупается. Это не обещание, что цена вернётся, и не рыночная продажа «в ноль» сразу после обрыва.

## Лимиты входов

Если реализованный результат дня вместе с открытым убытком просел на `SPOT_DAILY_LOSS_BPS` (по умолчанию 500, это 5% утренней кассы плюс себестоимость уже открытых монет), новые входы в этой книге до завтра не открываются. Сутки считаются по UTC. В первый цикл нового дня утренняя наличность фиксируется до выходов этого цикла: и уже открытый убыток, и убыток, закрытый в этом же цикле, входят в дневной лимит. Если утром не было ни кассы, ни монеты, закрытый в этот день убыток всё равно запрещает новый вход. Себестоимость открытой монеты в утреннюю сумму входит: остаток кассы после покупки её не заменяет. Плюс по открытой позиции этот порог не уменьшает. Выходы при этом продолжаются.

Просадка считается от пика кассы с открытыми монетами по `SPOT_DRAWDOWN_BPS` (по умолчанию 1000, это 10%). Монета в этой оценке — бид после комиссии тейкера пары, не голая сумма. Если эту комиссию прочитать нельзя, новый вход не открывается. Если цену открытой позиции прочитать не удалось, новый вход не открывается. Отрицательная оценка кассы новые входы закрывает. Пик кассы поднимается только вверх.

## Фильтры пары

Покупка читает `exchangeInfo` пары. Книга, последняя цена и правила пары принимаются только если в ответе имя этой пары. Две строки правил одной пары не кэшируются. Заявка без пары, номера или размера не уходит.

Комиссия берётся из `takerCommission` этой пары и округляется вверх. Нулевая комиссия с биржи остаётся нулевой и в медиану прогона не идёт. `SPOT_TAKER_BPS` — запас для бумажного счёта, когда своей комиссии пары ещё нет. Лот округляется до `baseSizePrecision`. `quoteAmountPrecisionMarket` — минимальный шаг суммы рыночной заявки, не число знаков: на USDT-парах 13 октября 2026 это `"1"`, то есть 1 USDT. Шаг цены берётся из `quotePrecision`. Нулевой шаг лота, нулевой минимум суммы и нулевой потолок суммы не становятся разрешением торговать. Булево значение не считается суммой, шагом лота, комиссией или вкладом в рукава. Число JSON и запись с показателем степени не считаются ценой, количеством или комиссией: биржа присылает десятичный текст. То же для комиссии пары, шага лота, шага суммы, потолка суммы, числа знаков цены, исполненного количества, номера ордера и цены Binance, Bybit и OKX: число JSON площадку из сверки выкидывает, а не подставляет как цену. Пара, у которой один шаг цены шире стопа, в сделку и в медиану не идёт.

Пара без типа MARKET, с пустым списком типов, со статусом не «торгуется», с меткой ST или с плитой Assessment в покупку не идёт. Имя монеты для продажи берётся из `baseAsset` и должно совпадать с парой. Покупка разрешена только если `tradeSideType` равен 1: пару можно и купить, и продать. Пустое поле и режим «только покупка» сделку не открывают. Уже открытая позиция при этом продаётся.

## Живая заявка

Если часы компьютера ушли от часов MEXC больше чем на 2 секунды или время биржи прочитать не удалось, живые заявки в этом цикле не отправляются: окно подписи 5 секунд. Позиция при этом остаётся. Время подписи берётся из целых наносекунд. Нулевая книга и время сервера не из целого числа отказывают. Два номера заявки в одну наносекунду не совпадают.

Перед живой заявкой её клиентский номер пишется в книгу. Клиентский номер — от 1 до 32 символов из букв, цифр, подчёркивания и дефиса, и только на USDT-паре. Номер ордера биржи, если он есть, состоит из цифр. Номер сделки и номер ордера в строке сделки — цифры, и в строке должно быть имя пары. Пока номер заявки не закрыт, вторая заявка, в том числе по другой монете, не отправляется и номер не затирается. Запись нового номера поверх уже открытого отвергается. Пока в другой книге того же счёта висит номер заявки, эта книга тоже не отправляет ордер. Покупка не пишется на строку с тем же номером клиента, но другой парой, и пустой номер клиента позицию не двигает.

Если процесс оборвался после отправки, следующий цикл читает ордер по этому номеру и записывает сделку один раз. Ответ с кодом ошибки биржи не считается заявкой, даже если HTTP-статус 200. Ответ другого типа или с объёмом больше отправленного в книгу не пишется. Чужой ответ — другая пара, сторона или номер — в книгу не пишется. Ответ живой заявки с чужим клиентским номером в книгу не пишется. Два разных клиентских номера в одном ответе заявку не подтверждают. Список сделок читается как список, а не как объект заявки. Первый номер ордера биржи закрепляется: следующий ответ с другим номером ту же заявку не закрывает.

Пока чтение заявки говорит, что её нет, номер не стирается. Текст «does not exist» без заявки номер не снимает. Если биржа три цикла подряд говорит, что заявки нет, и в книгу по ней ещё ничего не записано, номер снимается. Ошибка самой отправки номер не стирает: заявка могла уже быть принята. Ненулевое количество, которое не читается, или нулевая сумма при таком количестве тоже номер не снимают. Нулевое количество в любой десятичной записи — пустой филл, а не снятие номера. Номер, который биржа уже подтвердила, не снимается ответом «заявки нет». Отмена, в которой биржа показывает ноль, не стирает уже записанное исполнение. Отмена без исполнения снимает ожидание. Отмена, в которой часть уже исполнилась, записывает только эту часть: у продажи остаток монеты остаётся в позиции. Если проверка остатка не проходит, номер заявки не снимается. Одна такая ошибка номер не стирает.

Частично исполненная живая заявка пишется в книгу по факту и не продаётся, пока биржа её не закрыла. Повтор того же объёма кассу второй раз не двигает. Повторное исполнение покупки не держит пик от более дорогого частичного объёма, если этот пик не поднимал рынок. Повтор того же исполнения покупки не закрывает заявку, если монеты с этим номером в книге уже нет, их количество или сумма не равны уже списанным, или цена входа не равна котировке, делённой на эти монеты. Пик такой покупки не может быть ниже цены входа. Живая покупка списывает сумму из ответа, а не запрошенную. Цена входа живой покупки — уплаченная котировка, делённая на полученную монету, а не тикер до заявки. Восстановленная покупка ставит цену входа по монете, которая осталась после комиссии, а не по полному объёму заявки. Покупка пишется только на свой номер, свою USDT-пару и не выше запрошенной суммы.

Если комиссию заявки прочитать не удалось, запись не закрывается и вторая заявка не отправляется. Комиссия USDT берётся из `myTrades` по номеру этой заявки, если её не было в ответе ордера. Если в списке сделок нет строки этого ордера, комиссия не считается нулём. Если страница сделок заявки заполнена до лимита, комиссия считается непрочитанной. Сумма строк должна совпасть с объёмом заявки, иначе комиссия неполная и заявка не закрывается. Строка без своего номера, повтор того же номера или чужая сторона заявку не закрывают. У строки сделки должна быть положительная цена, и цена на количество должна попасть в сумму строки с точностью до одной миллионной USDT.

Комиссия, снятая купленной монетой, уменьшает позицию. Комиссия в третьей монете заявку не закрывает. Комиссия, которая не помещается в кассу или в сумму сделки, не обрезается: заявка остаётся открытой. Записанная комиссия не больше записанной суммы сделки. Комиссия в ответе заявки не в USDT и не равная списку сделок не считается нулём. Если на том же объёме комиссия стала больше, разница списывается; если стала меньше, заявка не закрывается. Если ответ продажи уже назвал комиссию, она должна совпасть со списком сделок. Если комиссия купленной монетой на том же объёме стала больше, позиция уменьшается на разницу; если стала меньше, заявка не закрывается. Живой ордер биржевую комиссию сам не дописывает второй раз.

В живом режиме перед новым входом книга сверяется с `GET /api/v3/account`: количество монеты должно совпасть, лишняя монета на счёте останавливает входы. Монета другого рукава на том же счёте лишней не считается: в сумму входят все три книги. USDT в этой сверке не сравнивается. Строка баланса без актива или не объектом не считается пустым счётом. Отрицательный баланс отвергается. Имя актива приводится к верхнему регистру. Один и тот же актив в счёте не складывается. Несовпадение или ошибка чтения счёта не открывает новую позицию. Выходы продолжаются.

Нечисловая цена свечи, стакана или ответа заявки остаётся ошибкой этой пары и не останавливает остальные рукава.

## Лимит биржи и сеть

HTTP 403, 418 и 429, и тот же код в теле ответа при HTTP 200, останавливают остаток этого цикла. Книга записывается, следующий рукав в этом проходе не стартует. Следующий цикл ждёт заголовок Retry-After, но не меньше двух минут, если заголовок не разобран, и не дольше трёх суток. Повтор внутри цикла не крутится. Ответ 429 или 418 останавливает остаток скана. Тот же ответ на одном рукаве не запускает следующий рукав в этом проходе.

Публичный и подписанный запрос, и цены других площадок, не идут по редиректу. Запросы к MEXC, Binance, Bybit и OKX не идут через прокси из окружения. Битый файл котировок не обрывает цикл и не смешивается с новой строкой.

## Страница наблюдения

Только `127.0.0.1:19280` (`SPOT_OPS_PORT`). Порт страницы только из цифр. Порты `18180–18182` она не занимает. Страница читает книги, последние цены сверки, сделки и журнал. Ордера с неё не отправляются, ключи на неё не попадают. Запись любым методом отказывает. Бот с флагом `--ops` поднимает ту же страницу внутри процесса. Отдельный просмотр: `python -m spotbot.ops_main`. Пока страница уже слушает этот порт, второй процесс на него не садится.

Ops показывает возраст последнего завершённого цикла. Битый файл книги, пульса или журнала не гасит страницу. Цена не из целого числа показывается как нечитаемая. Имена и текст на странице вставляются как текст, не как разметка.

## Прогон по свечам

`python -m spotbot.replay_main` печатает результат RSI и свечную половину правила ликвидности на раннем и позднем куске одной ленты, и ту же медиану отдельно по книгам major, alt и meme. Правило на трёх книгах одно. Параметры на кусках одни и те же и на ленте не подбирались. Покупка исполняется по открытию следующей свечи, не по свече сигнала, и только если это открытие всё ещё выше нижней полосы и предыдущего закрытия и не дальше 15% от закрытия сигнала. Живой аск с тем же отрывом уже отвергается. Продажа идёт по первому минутному закрытию, на котором выход уже сработал, а не по закрытию пятиминутной свечи и не по теоретической цене стопа. Исторического бида в ленте нет. Покупка и продажа в прогоне хуже сырой цены на 30 bps. Стоп, тейк и трейл видят эту же ухудшенную цену. Это тот же потолок спреда, который живая покупка уже отвергает, а не исторический спред ленты.

«Просто держать» покупает ту же долю кассы, что и правило. Пока позиция открыта, её оценка печатается отдельно и из удержания не вычитается. Медиана — это закрытые сделки плюс оценка ещё открытой позиции. Если цену открытой позиции посчитать нельзя, пара в медиану не идёт и ноль не печатается. Пара с комиссией 0 в медиану не идёт. Вторая строка прогона не включает стакан и оракул, поэтому это не живое правило. Плюс одного куска не включает стакан и не ставит лимитную продажу.

## Переменные

Пустые ключи в `.env.example`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MEXC_API_KEY`, `MEXC_API_SECRET` | пусто | Нужны только для живых ордеров |
| `SPOT_SYMBOLS` | BTC, ETH, SOL | Список бумажного цикла без `--sleeves` |
| `SPOT_PAPER_CASH_USDT` | 1000 | Стартовая бумажная касса |
| `SPOT_INTERVAL_SEC` | 60 | Пауза между циклами |
| `SPOT_LIVE` | 0 | Живые ордера только вместе с `--live` и значением `1` |
| `SPOT_ENTRIES` | 0 | Не включает входы. Измеренное правило после комиссии в минусе |
| `SPOT_TAKER_BPS` | 5 | Запасная комиссия, если у пары своей ещё нет |
| `SPOT_DAILY_LOSS_BPS` | 500 | Дневной предел убытка, 5% |
| `SPOT_DRAWDOWN_BPS` | 1000 | Просадка от пика кассы, 10% |
| `SPOT_STOP_COOLDOWN_SEC` | 900 | Пауза входов после стопа |
| `SPOT_STOP_LOCK_COUNT` | 3 | Сколько стопов одной пары запирают её |
| `SPOT_STOP_LOCK_SEC` | 14400 | На сколько секунд пара запирается |
| `SPOT_SPREAD_BPS` | 30 | Шире этого спреда покупка не идёт |
| `SPOT_OPS_PORT` | 19280 | Страница наблюдения, только localhost |
